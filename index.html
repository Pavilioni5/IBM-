Namespace Isolation.

Three environments — dev, test, and prod — deployed as logically isolated slices of a single Minikube cluster, each running its own NGINX Deployment, ReplicaSet, and Service.

minikube v1.38.1 kubectl v1.35.2 Docker 29.2.1 nginx:latest / nginx:1.25 3 namespaces
01

Architecture

A single control plane, three isolated environments. Each namespace gets its own copy of the same Deployment/Service shape — this is the whole thesis of the project.

NAMESPACE

Logical partition inside one cluster. dev/test/prod never see each other's Pods or Services by default.

DEPLOYMENT

Declares desired replica count and Pod template; owns a ReplicaSet per revision.

REPLICASET

Keeps the declared number of Pods alive — created and rotated automatically by the Deployment.

SERVICE

Stable ClusterIP + DNS name (nginx-service.<ns>.svc) that load-balances across matching Pods via label selector.

Manifests

Every namespace ships the same two files: a Deployment and a Service.

deployments/nginx-dev.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
  namespace: dev
spec:
  replicas: 2
  selector:
    matchLabels: { app: nginx }
  template:
    metadata:
      labels: { app: nginx }
    spec:
      containers:
      - name: nginx
        image: nginx:1.25
        ports:
        - containerPort: 80
services/nginx-dev-service.yaml
apiVersion: v1
kind: Service
metadata:
  name: nginx-service
  namespace: dev
spec:
  selector: { app: nginx }
  ports:
    - protocol: TCP
      port: 80
      targetPort: 80
  type: ClusterIP

Verification & scaling

Confirmed live with kubectl scale — each namespace was independently resized without touching the others.

CommandEffect
kubectl scale deployment nginx-deployment --replicas=5 -n devdev scaled 2 → 5, other namespaces unaffected
kubectl scale deployment nginx-deployment --replicas=2 -n testtest scaled 1 → 2
kubectl scale deployment nginx-deployment --replicas=5 -n prodprod scaled 3 → 5
This is the actual proof of isolation: scaling one namespace's Deployment has zero effect on Pod counts in the other two — because the ReplicaSet selectors and namespaces are fully partitioned.

Rolling update — dev

Updating the image from nginx:latest to nginx:1.25 in dev triggered a zero-downtime RollingUpdate.

$ kubectl rollout status deployment/nginx-deployment -n dev
Waiting: 1 out of 2 new replicas have been updated...
Waiting: 1 old replicas are pending termination...
deployment "nginx-deployment" successfully rolled out

$ kubectl rollout history deployment/nginx-deployment -n dev
REVISION  CHANGE-CAUSE
1         <none>
2         <none>
Old ReplicaSet nginx-deployment-59f86b59ff scaled to 0, new ReplicaSet nginx-deployment-5fd577784b took over — this is the RollingUpdate strategy (max unavailable 25%, max surge 25%) in action.
07

Troubleshooting notes

Real issues hit during the build, and how they were resolved.

minikube service — "No node port" / browser not found in WSL+
ClusterIP services aren't externally reachable by design. minikube service opened a tunnel on 127.0.0.1:41865, but WSL has no GUI browser to auto-launch — the tunnel itself worked, only the auto-open step failed. Fix: copy the printed URL into any browser manually, or use kubectl port-forward.
kubectl logs "<pod> not found in namespace default"+
Forgot the -n dev flag — kubectl defaults to the default namespace on every command unless a namespace is explicitly passed or a context override is set.
Pod stuck in ContainerCreating during scale-up+
Transient — seen briefly while scaling prod to 5 replicas as the image layer was being reused/pulled. Resolved by re-checking kubectl describe pod <name> -n prod and kubectl get events -n prod, which is the standard first move for any stuck pod.

Glossary

Terms worth having crisp definitions for if asked.

Namespace
A virtual cluster-within-a-cluster; scopes names, RBAC, and resource quotas.
Pod
The smallest deployable unit — one or more containers sharing network/storage.
ReplicaSet
Ensures N Pod replicas are running at all times; managed indirectly via Deployments.
Deployment
Declarative controller for Pods/ReplicaSets — handles rollouts, rollbacks, and scaling.
Service
Stable virtual IP + DNS name that load-balances traffic to Pods matching a label selector.
ClusterIP
Default Service type — reachable only from inside the cluster.
